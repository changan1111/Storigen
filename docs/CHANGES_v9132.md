# v9.13.2

Built on 9.13.1. Nothing in the attach rules changed; the tool now also **shows each story's script**.

* **Two script boxes.** Every story card, and the "Selected story" details, show the two script fields Blaze keeps for the story: `storyComplete` -> `versions[0].items[]` -> `text1` (box 1, default name "Online script": reporter, place and on-screen lines) and `text2` (box 2, default name "Anchor script": the anchor's read). The card shows the first 400 characters, the details show the whole text with a Copy button. Tamil and any other script display as sent. The boxes sit next to the existing buttons, including **Quick test attach**, which is unchanged. The names of the boxes are `SCRIPT_LABEL_ONLINE` and `SCRIPT_LABEL_ANCHOR` in autoid.env.
* **Where it comes from.** The poller (`blaze/scripts.py`) reads `GET /DataService/stories/<id>/complete/` (the call it already makes for attaching) for every story of the followed shows and sends the two texts to the registry (`POST /svc/scripts`), which stores them on the story (database schema 7: `stories.online_script`, `anchor_script`, `script_at`). A story with several items gets the items' texts in `arrangeOrder`, a blank line between. Reading only: nothing is ever written to Blaze.
* **Stories already in the database.** The first time the new poller runs, every story of the followed shows is read once (`BLAZE_SCRIPT_BATCH` per round, 40 by default: about 5 minutes for 700 stories at the 15 s poll). A story that is new in the rundown is read in the next round. Before its first read a card says "Script: not read from Blaze yet".
* **Edits in Blaze** reach the dashboard within `BLAZE_SCRIPT_SECS` (120 s by default). Only changed text is sent and written.
* **Safe by design.** The dashboard list carries only the 400-character preview (a 700-story day stays light every 5 s). Script text is put on the page as plain text, never as HTML. A problem while reading scripts is said once in the log and never stops the polling round. `BLAZE_SCRIPTS=0` switches the reading off.
* **Upgrade.** Copy the new program files over the old ones (never `autoid.env` or the `data` folder), then restart the one service that runs everything (`autoid.py run` starts the web server and the Blaze poller together). The server upgrades the database by itself and keeps all data. Details: README "Upgrading". A new poller with an old server, or the reverse, is harmless: the poller says once that it could not send the scripts and tries again every round.
* **Tests:** `test_story_scripts.py` (13 new); the two version checks now expect 9.13.2.
