# v9.13.1

Built on the restructured 9.13. Nothing in the attach rules changed; the tool now **shows** what it already knew.

* **Why a clip is not attached, on its card.** Under the steps, each waiting clip has an "Attach status" line: "Not in Blaze's media list yet", "File found: waiting until Blaze has not changed it for 60 s", "Blaze is still converting the file", "Dry mode: nothing is sent by itself ... Use Quick test attach", "Blocked: <the rule>" (for example "story 731375 is not QUICKTEST_STORY_ID"), "The poller does not follow show N", "New version: the desk attaches it", "N Blaze files carry this ID". The poller already worked these out and only wrote them to the log. They go to the dashboard through the new `POST /svc/why` and are kept in memory (sent again every round; hidden if the poller is silent for two minutes). No database change.
* **Warning when autoid.env was edited but not applied.** The poller reads autoid.env once, at start. Every 20 s it compares the settings that decide what is attached and when (BLAZE_ATTACH, BLAZE_ATTACH_WHEN, BLAZE_SHOW_IDS, BLAZE_LIVE_*, QUICKTEST_*, BLAZE_VERSION_MODE, BLAZE_POLL_SECS, BLAZE_MEDIA_SETTLE_SECS) with the file. If they differ, the dashboard problem list says "autoid.env was changed but the Blaze poller still runs the old settings (...). Restart the service", the poller logs `SETTINGS CHANGED in autoid.env but NOT applied`, and the usual alert goes out. The warning goes away after a restart. The session cookie is not in the list (it is re-read by itself).
* **One poller at a time.** `blaze_poll.py run` takes `data/blaze_poll.lock` before it does anything else (before it can log in). A second copy stops at once and says which pid started when holds the lock. The operating system frees the lock when a process ends, also after a crash. Read-only commands (`live`, `report`, `map`, `once`, ...) do not use the lock. `BLAZE_POLL_NO_LOCK=1` switches it off. The Windows branch of the lock is written but, like the Windows installer, not tested on a real Windows machine.
* **Heartbeat** from the poller now also carries its pid and start time.
* **Tests:** `test_attach_status_on_cards.py`, `test_settings_drift_warning.py`, `test_single_poller_lock.py` (12 new); the two version checks now expect 9.13.1.
* The Install and Operations Guide PDF still says 9.13.
