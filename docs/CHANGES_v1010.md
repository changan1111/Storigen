# v10.1.0 - Play the clip from Nitro in the dashboard (nothing is stored)

* New **Preview (low resolution)** box in the Media & IDs pane with a **Play from Nitro** button. It is enabled once the clip's file is on Nitro (the ONAIR folder, current date folder). It plays a small 360p preview and shows the file length next to the length attached in Blaze, so the desk can check the right clip is attached.
* **Nothing is stored.** No cache, no temp file, nothing written in the project or anywhere else. Each Play runs ffmpeg, which converts the MXF to H.264/AAC while sending it straight to the browser (`GET /api/clips/<id>/preview`, login required like every other call). The preview starts in about a second or two on a normal file. There is no seek bar: it always plays from the start (press Play again to restart).
* **Light on the rest of the system:** it only runs when someone presses Play; ffmpeg runs at low CPU priority with 2 threads; one preview at a time by default (a second person is told "Another preview is running, try again in a moment"); it stops at once when the page is closed, another story is chosen or Stop is pressed, and after PREVIEW_MAX_SECONDS (900) in any case. The poller, watcher and the rest of the dashboard are not touched.
* **Safe:** only the file recorded for that clip is streamed, and only if it is inside NITRO_DIR (links and `..` are resolved first).
* Settings (autoid.env, see the PREVIEW block): PREVIEW_ENABLED (0 removes the button), PREVIEW_MAX_JOBS, PREVIEW_HEIGHT, PREVIEW_THREADS, PREVIEW_MAX_SECONDS. Restart the web service after changing them.
* Needs: ffmpeg installed on the machine that runs the web service, and that machine must see NITRO_DIR at the same path as the watcher. If either is missing the button says so; nothing else is affected.
* Files: new `autoid_lite/preview.py`; changed `server.py` (stream support), `api_dashboard.py`, `api_auth.py`, `web/index.html`, `common.py` (version 10.1.0), `autoid.env.example`; new `tests/test_preview.py`. No database or poller change.
